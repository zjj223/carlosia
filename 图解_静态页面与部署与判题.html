静态页面 / 部署 / 判题
三件事到底是什么关系

一句话先说清：静态页面是「东西本身」，部署是「把东西放到别人拿得到的地方」，判题是「一台会真的跑代码的机器」。 三者不是三种软件，是同一套东西的三个位置。

1

三件事，各自是什么

东西本身

静态页面

一堆文件，不会「运行」

就是 index.html、app.js、styles.css，加上 assets/ 里 164MB 的宠物图和场景图。 浏览器拿到它们，只是「显示出来」；分数、战斗、洛克贝全在你浏览器里算。

你双击 index.html 就能玩，是因为这些文件全在你自己的硬盘上。

放到哪

部署

把同一批文件搬到服务器上

复制到服务器的 /srv/game，再装一个叫 nginx 的程序，专门干一件事：有人来要文件，就给他发过去。

代码一个字都不用改。改的只是「文件放在哪」和「谁负责发」。

谁来算

判题

一台真的会编译、会运行 C++ 的机器

学生点「编译运行」，代码被发到服务器的容器里，用 gcc 编译、跑 2 秒、把输出和报错发回来。

你电脑上没有 Linux 和 gcc，也没法让 60 个学生的代码在你机器上跑——所以这件事只能在服务器做。

5

四个最容易搞混的地方

×
部署 = 把代码重新写一遍
不是。就是把同一批文件 git clone 到服务器，再装 nginx。你本地那份和服务器那份内容完全一样。
×
本地双击能玩，所以不用服务器
不是。你玩的是「自己硬盘上的文件」。服务器的作用是给别人的浏览器一个能打开的地址。
×
Dev-C++ 预览页就是判题
不是。预览页只是「遥控器」：长得像 Dev-C++，负责发代码、显示结果。真编译在服务器容器里。
×
60 个人用，多买几台机器就行
不是。先卡的是带宽（164MB 素材）、判题并发、同屏 50 人上限。这些先解决，再谈加机器。
